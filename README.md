# Кошелёк путешественника

Telegram-бот для учёта расходов в поездке. Ведёт баланс сразу в двух валютах (домашняя и валюта назначения), подтягивает курс с `api.exchangerate.host` и позволяет задать курс вручную.

Интерфейс на русском. Данные хранятся локально в SQLite.

---

## Возможности

- Создание путешествия с парой валют и стартовой суммой
- Автоматический курс через API или ручной ввод
- Быстрый учёт расходов: достаточно отправить число в чат
- Баланс в двух валютах и история последних трат
- Несколько поездок с переключением активной
- Смена курса у текущей поездки без пересчёта уже накопленного остатка
- После завершённых сценариев (создание поездки, смена курса, расход) чат очищается до одного сообщения с главным меню

## Стек

| Компонент | Назначение |
|-----------|------------|
| Python 3.10+ | runtime |
| aiogram 3.x | Telegram Bot API, FSM |
| aiosqlite | асинхронная SQLite |
| httpx | HTTP-запросы к сервису курсов |
| pydantic / pydantic-settings | валидация настроек из `.env` |
| python-dotenv | загрузка переменных окружения |

**Ограничение по курсам:** используется только  
`http://api.exchangerate.host/convert`  
с обязательным параметром `access_key`. Другие API не применяются.

## Быстрый старт

### 1. Клонирование и окружение

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

На Linux / macOS:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Ключи

1. Создайте бота у [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Зарегистрируйтесь на [exchangerate.host](https://exchangerate.host/) и получите `access_key`.

### 3. Файл `.env`

Скопируйте пример и заполните значения:

```powershell
Copy-Item .env.example .env
```

Содержимое:

```env
BOT_TOKEN=123456789:AA...ваш_токен_от_BotFather
API_KEY=ваш_access_key_от_exchangerate.host
DB_PATH=wallet.db
```

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `BOT_TOKEN` | да | токен Telegram-бота |
| `API_KEY` | да | `access_key` для `api.exchangerate.host` |
| `DB_PATH` | нет | путь к файлу SQLite (по умолчанию `wallet.db`) |

Файл `.env` не должен попадать в git (см. `.gitignore`).

### 4. Запуск

```powershell
.\venv\Scripts\python.exe main.py
```

В консоли должно появиться roughly:

```text
INFO:__main__:Бот запущен, база: wallet.db
INFO:aiogram.dispatcher:Start polling
INFO:aiogram.dispatcher:Run polling for bot @your_bot ...
```

Откройте бота в Telegram и отправьте `/start`.

Остановка: `Ctrl+C` в терминале.

## Как пользоваться

### Главное меню

Появляется после `/start` и после завершения основных операций:

| Кнопка | Действие |
|--------|----------|
| Создать новое путешествие | диалог создания поездки |
| Мои путешествия | список поездок, выбор активной |
| Баланс | остаток активной поездки в двух валютах |
| История расходов | последние до 10 трат |
| Изменить курс | обновление курса активной поездки |

### Команды

| Команда | Описание |
|---------|----------|
| `/start` | приветствие и меню |
| `/newtrip` | создать путешествие |
| `/switch` | переключить активную поездку |
| `/balance` | показать баланс |
| `/history` | история расходов |
| `/setrate` | изменить курс |

### Создание путешествия

1. Страна отправления или код валюты (`Россия`, `RUB`).
2. Страна назначения или код (`Китай`, `CNY`).
3. Бот запрашивает курс у API и показывает, например:  
   `Текущий курс: 1 CNY = 12.8 RUB`.
4. Подтвердите курс или введите свой.
5. Укажите стартовую сумму в **домашней** валюте.
6. Поездка сохраняется и становится единственной активной.

Название поездки берётся из введённой страны назначения (или из кода валюты).

### Расходы

При активной поездке отправьте число, например `100` или `100.50`:

1. Бот считает эквивалент по сохранённому курсу:  
   `расход в валюте назначения × курс`.
2. Спрашивает подтверждение.
3. Если остаток уйдёт в минус — спрашивает ещё раз.
4. После «Да» списывает оба баланса и пишет запись в историю.

Курс в базе хранится как:

> **1 единица валюты назначения = X единиц домашней валюты**

### Смена курса

Через кнопку «Изменить курс» или `/setrate`. Бот снова предлагает курс API или ручной ввод. Уже накопленные остатки **не пересчитываются** — меняется только курс для следующих расходов.

## База данных

### `users`

| Поле | Тип | Описание |
|------|-----|----------|
| `user_id` | INTEGER PK | Telegram user id |
| `home_currency` | TEXT | домашняя валюта (по умолчанию `RUB`) |

### `trips`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | id поездки |
| `user_id` | INTEGER FK | владелец |
| `name` | TEXT | название |
| `home_currency` | TEXT | валюта отправления |
| `target_currency` | TEXT | валюта назначения |
| `exchange_rate` | REAL | 1 target = X home |
| `is_manual_rate` | BOOLEAN | курс введён вручную |
| `home_balance` | REAL | остаток в домашней валюте |
| `target_balance` | REAL | остаток в валюте назначения |
| `is_active` | BOOLEAN | активная поездка (не больше одной на пользователя) |

### `expenses`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INTEGER PK | id расхода |
| `trip_id` | INTEGER FK | поездка |
| `amount_target` | REAL | сумма в валюте назначения |
| `amount_home` | REAL | эквивалент в домашней |
| `timestamp` | DATETIME | время записи |
| `description` | TEXT | необязательное описание |

Основные функции: `init_db`, `create_user`, `create_trip`, `get_active_trip`, `list_trips`, `switch_trip`, `add_expense`, `update_balance`, `update_exchange_rate`, `get_expenses`.

## API курсов

Запрос всегда такого вида:

```http
GET http://api.exchangerate.host/convert?access_key=...&from=RUB&to=CNY&amount=1
```

Клиент: `api_client.get_exchange_rate(from_currency, to_currency, amount, api_key)`.

При `success: false` пользователь получает понятное сообщение:

- неверный ключ → просьба проверить `API_KEY` в `.env`;
- неверная валюта → проверить название страны или код;
- сеть / лимиты / прочий отказ → сервис временно недоступен, можно ввести курс вручную.

В логах консоли ключ маскируется (`access_key=***`), а шумные INFO-логи `httpx` отключены.

## Валюты и страны

Кроме трёхбуквенных кодов (`RUB`, `CNY`, `EUR`…) бот понимает распространённые названия стран на русском и английском (`Китай` → `CNY`, `Япония` → `JPY` и т.д.). Список задан в `handlers/common.py`. Неизвестный ввод не подменяется: бот попросит уточнить валюту.

## Обработка ошибок (UX)

| Ситуация | Поведение |
|----------|-----------|
| Не число | просьба ввести корректное число (`150` или `150.50`) |
| Нет активной поездки | предложить создать путешествие |
| Расход уводит баланс в минус | дополнительное подтверждение |
| Ошибка API | сообщение о недоступности + возможность ручного курса |
| Неверный `API_KEY` | ошибка конфигурации с отсылкой к `.env` |

## Очистка чата

После успешного создания поездки, смены курса или подтверждения/отмены расхода бот:

1. сразу показывает итоговое сообщение с кнопками главного меню (редактирует своё последнее сообщение, если можно);
2. затем удаляет остальные сообщения этого диалога, которые видел в текущем запуске.

Сообщения старше ~48 часов Telegram может не дать удалить — они останутся в истории.

## Безопасность

- Храните `BOT_TOKEN` и `API_KEY` только в `.env`, не коммитьте их.
- При утечке ключа в логах или чате — перевыпустите ключ на стороне сервиса и обновите `.env`.
- База `wallet.db` содержит персональные данные переписки расходов: не публикуйте файл.

## Типичные проблемы

**`BOT_TOKEN не задан` / `API_KEY не задан`**  
Проверьте `.env`: нет заглушек `your_bot_token_here` / `your_access_key_here`.

**Бот не отвечает**  
Убедитесь, что `main.py` запущен и в консоли идёт polling. Второй экземпляр polling с тем же токеном конфликтует — остановите лишний процесс.

**Курс не получается**  
Проверьте интернет, квоту ключа и корректность кода валюты. Можно нажать «Ввести вручную».

**После перезапуска «пропали» незавершённые диалоги**  
FSM хранится в памяти процесса (`MemoryStorage`). После рестарта незакрытые шаги сбрасываются; данные в SQLite остаются.
