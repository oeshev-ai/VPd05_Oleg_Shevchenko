### Промпт для Cursor: Telegram-бот "Кошелёк путешественника"

**Роль:** Ты — экспертный Python-разработчик, специализирующийся на создании асинхронных Telegram-ботов с использованием `aiogram 3.x`, `aiosqlite` и `httpx`. Ты пишешь чистый, типизированный (type hints), модульный код с подробными комментариями на русском языке и строго следуешь бизнес-логике.

**Цель:** Создать Telegram-бота, который работает как миникошелёк для путешественника. Бот отслеживает расходы в поездке, конвертирует валюты и ведёт баланс в двух валютах одновременно.

---

### ЖЁСТКИЕ ОГРАНИЧЕНИЯ (СТРОГО СОБЛЮДАТЬ)
1. **API:** Использовать **СТРОГО** и **ТОЛЬКО** `api.exchangerate.host`. Никакие другие API (например, exchangerate-api.com, frankfurter и т.д.) использовать запрещено.
2. **Endpoint:** Все запросы на конвертацию должны идти строго на `http://api.exchangerate.host/convert`.
3. **Аутентификация:** Запрос должен обязательно содержать параметр `access_key`, который читается из переменных окружения (`.env`). Бесплатные/тестовые эндпоинты без ключа не использовать.
4. **Хранение:** Только локальная база данных SQLite (`aiosqlite`). Никаких внешних БД.
5. **Язык интерфейса:** Русский. Все сообщения об ошибках должны быть дружелюбными и понятными.

### Схема базы данных (SQLite)
Создай миграции или функцию инициализации БД со следующими таблицами:
1. **`users`**
   - `user_id` (INTEGER, PRIMARY KEY)
   - `home_currency` (TEXT, DEFAULT 'RUB') — домашняя валюта пользователя.
2. **`trips`**
   - `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
   - `user_id` (INTEGER, FOREIGN KEY -> users.user_id)
   - `name` (TEXT) — название поездки (например, "Китай 2024")
   - `home_currency` (TEXT) — валюта отправления (например, 'RUB')
   - `target_currency` (TEXT) — валюта назначения (например, 'CNY')
   - `exchange_rate` (REAL) — курс обмена (1 единица target = X home)
   - `is_manual_rate` (BOOLEAN) — флаг, был ли курс введён вручную
   - `home_balance` (REAL) — текущий остаток в домашней валюте
   - `target_balance` (REAL) — текущий остаток в валюте назначения
   - `is_active` (BOOLEAN, DEFAULT 0) — только одна активная поездка на пользователя
3. **`expenses`**
   - `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
   - `trip_id` (INTEGER, FOREIGN KEY -> trips.id)
   - `amount_target` (REAL) — сумма расхода в валюте назначения
   - `amount_home` (REAL) — эквивалент в домашней валюте
   - `timestamp` (DATETIME, DEFAULT CURRENT_TIMESTAMP)
   - `description` (TEXT, NULLABLE)

### Бизнес-логика и User Flow

#### 1. Старт и создание путешествия (`/newtrip` или кнопка "Создать новое путешествие")
- Запускается FSM (Finite State Machine).
- **Шаг 1:** Бот спрашивает: "Введите страну отправления (или код валюты, например, RUB)".
- **Шаг 2:** Бот спрашивает: "Введите страну назначения (или код валюты, например, CNY)".
- **Шаг 3:** Бот делает запрос к `http://api.exchangerate.host/convert?access_key=YOUR_KEY&from=RUB&to=CNY&amount=1`. 
  - *Обработка ошибок API:* Если ошибка, вежливо сообщить: "Не удалось получить курс. Проверьте название страны/валюты или попробуйте позже".
- **Шаг 4:** Бот показывает: "Текущий курс: 1 CNY = 12.8 RUB. Подходит ли вам этот курс?" (Inline-кнопки: `✅ Да`, `✏️ Ввести вручную`).
- **Шаг 5 (если вручную):** Бот просит ввести числовой курс.
- **Шаг 6:** Бот просит ввести начальную сумму в домашней валюте (например, 10000).
- **Шаг 7:** Бот конвертирует эту сумму через API (или по указанному курсу), создаёт запись в БД, устанавливает `is_active=1` для этой поездки и выводит: "Путешествие создано! Стартовый баланс: 10000 RUB = 781.25 CNY".

#### 2. Обработка числовых сообщений (Логика расходов)
- Если пользователь присылает сообщение, которое является числом (например, `100` или `100.50`), и у него есть **активное путешествие**:
  - Бот НЕ сохраняет расход сразу.
  - Бот считает: `100 * exchange_rate`.
  - Бот отправляет сообщение: "💸 Расход: `100 CNY` = `1280 RUB`. Учесть как расход?"
  - Inline-кнопки: `✅ Да` (callback: `confirm_expense:100`), `❌ Нет` (callback: `cancel_expense`).
  - При нажатии `✅ Да`: списывается из `target_balance` и `home_balance`, создаётся запись в `expenses`, выводится обновлённый баланс: "Остаток: 2400 CNY = 30 720 RUB".

#### 3. Главное меню (Inline-клавиатура)
Клавиатура должна появляться при `/start` и после завершения основных операций. Кнопки:
- `🌍 Создать новое путешествие`
- `🎒 Мои путешествия` (показывает список с возможностью переключить активное через callback)
- `💰 Баланс` (показывает текущий баланс активной поездки в двух валютах)
- `📜 История расходов` (последние 5-10 трат с датой и суммами)
- `⚙️ Изменить курс` (запускает FSM для обновления курса текущей активной поездки)

#### 4. Слэш-команды (альтернатива меню)
- `/start` — приветствие и главное меню.
- `/newtrip` — начать создание поездки.
- `/switch` — показать список поездок для переключения.
- `/balance` — показать текущий баланс.
- `/history` — показать историю расходов.
- `/setrate` — изменить курс для активной поездки.

### 🛡 Обработка ошибок (Friendly UX)
- **Не число:** "Пожалуйста, введите корректное число (например, 150 или 150.50)."
- **Нет активной поездки:** "У вас пока нет активного путешествия. Создайте его через кнопку 'Создать новое путешествие'."
- **Отрицательный баланс:** "⚠️ Внимание! Эта операция уведёт баланс в минус. Вы уверены?" (добавить подтверждение).
- **Ошибка API:** "🌐 Сервис курсов валют временно недоступен. Попробуйте ввести курс вручную или повторите позже."
- **Неверный access_key:** "⚙️ Ошибка конфигурации API. Проверьте параметр access_key в .env файле."

### Пошаговая инструкция для генерации кода (выполни по порядку)
1. Создай файл `requirements.txt` и `.env.example`.
2. Напиши `config.py` для строгой валидации `API_KEY`.
3. Напиши `database.py` с функциями: `init_db`, `create_user`, `create_trip`, `get_active_trip`, `switch_trip`, `add_expense`, `update_balance`, `get_expenses`.
4. Напиши `api_client.py` с функцией `get_exchange_rate(from_currency, to_currency, amount, api_key)`, которая делает запрос строго на `http://api.exchangerate.host/convert`.
5. Напиши `states.py` с классами `TripCreationState` и `RateUpdateState`.
6. Напиши `keyboards.py` с удобными фабриками callback-данных (например, `trip_cb`, `expense_cb`).
7. Напиши хендлеры в папке `handlers/`, обеспечив логику: числовое сообщение → расчёт → inline-кнопки → подтверждение → обновление БД.
8. Напиши `main.py`, который собирает всё вместе, регистрирует роутеры и запускает бота.

**Важно:** Перед генерацией кода убедись, что все callback-данные не превышают лимит Telegram (64 байта). Используй сокращения, если необходимо (например, `exp_conf:100.5` вместо полных слов).
